## 0. 한눈에 보기

- **엔진(Rust)**: 디코딩, 썸네일 캐시, 변환, 유사도 분석, 파일 작업을 맡는다. UI 기술과 분리되어 있어서 나중에 화면 기술을 바꿔도 엔진은 그대로 쓴다.
- **화면(Tauri 2 + Svelte)**: 윈도우와 맥을 한 코드로 만든다. 설치 파일은 약 10MB.
- **속도 원칙**: "지금 보는 사진"이 항상 1순위다. 썸네일 생성, 유사도 분석 같은 나머지 작업은 사용자가 사진을 넘기는 동안 **자동으로 멈추는** 백그라운드 작업으로 돌린다.
- **속도 측정**: 0단계에서 측정 도구를 먼저 만든다. 기능을 추가할 때마다 측정하고, 목표보다 느려지면 **사용자에게 보고하고 기능 제거 여부를 묻는다** (요구사항 1).

**iSee의 차별점**
1. **윈도우와 맥 모두 지원**: 알씨와 FastStone은 윈도우 전용이고 Peakto는 맥 전용이다.
2. **색인 없이 바로 보기**: Tonfotos와 Peakto는 라이브러리 전체를 먼저 색인해야 한다. 사용자 후기 기준으로 Tonfotos는 70GB 색인에 42분이 걸렸다. iSee는 폴더를 열면 바로 보이고, 색인은 백그라운드에서 조금씩 한다.
3. **로컬 처리**: Evoto는 대부분 클라우드에서 처리하고 크레딧을 받는다. iSee는 모든 분석을 내 컴퓨터에서 한다.
4. **빠른 보기와 유사 사진 정리를 한 흐름으로**: 유사 그룹 → 베스트 추천 → 비교 → 나머지 삭제가 한 화면에서 이어진다.

### 1-3. 리버스 엔지니어링에 대해

알씨는 **바이너리를 디컴파일하지 않고 기능 단위로 분석**했다. 이유는 세 가지다.
- 알씨는 윈도우 전용이라 이 맥에는 설치되어 있지 않다.
- 상용 프로그램을 내려받아 디컴파일하면 사용권 계약(EULA)에 걸릴 수 있다.
- 필요한 것은 알씨의 코드가 아니라 **기능과 사용 흐름**이다. 구현은 iSee가 독자적으로 한다.

> 윈도우 PC에 알씨가 있다면 **우클릭 메뉴와 변환 창 스크린샷**을 보내 주세요. 메뉴 구성과 순서를 거기에 맞추겠습니다.

### 2-1. 후보 비교

### 2-2. 추천: Tauri 2 + Rust 엔진 + Svelte

- 무거운 일(디코딩, 썸네일, 변환, 분석, 파일 작업)은 전부 **Rust 엔진**이 한다. 웹뷰는 결과를 그리기만 한다.
- **속도 위험과 대응**: 웹뷰는 앱을 처음 켤 때 0.1~0.5초가 더 든다.
  - 대응 1: **상주 모드**(옵션). 창을 닫아도 엔진과 창을 숨겨 두고, 다음에 사진을 더블클릭하면 0.1초 안에 뜬다.
  - 대응 2: 0단계에서 측정해 목표에 못 미치면 보고한다. 그때는 **사진 표시 화면만** 네이티브 GPU로 바꿀 수 있다. 엔진이 분리되어 있어서 바꿀 범위가 작다.

## 3. 속도 설계 (가장 중요)

### 3-1. 단계별 표시: 흐리게 먼저, 선명하게 곧바로

| 순서 | 무엇을 보여주나 | 목표 시간 |
|---|---|---|
| ① 즉시 | 캐시된 썸네일 또는 EXIF 내장 썸네일을 화면 크기로 늘려서 표시 | 10ms 이내 |
| ② 화면 해상도 | JPEG는 **화면 크기에 맞는 배율만 디코딩**. RAW·PSD·HEIC는 파일 안의 미리보기 이미지를 사용 | 30~50ms |
| ③ 원본 해상도 | 100% 이상 확대할 때만, **보이는 부분(타일)만** 디코딩 | 확대 시점에 |

4000만 화소 사진도 모니터 크기(약 400만 화소)만큼만 디코딩하면 되므로 10배 가까이 빨라진다.

### 3-2. 미리 불러오기

- 다음·이전 사진 2~3장을 미리 디코딩한다. 넘기는 방향을 보고 앞쪽을 더 많이 준비한다.
- 메모리 한도를 넘으면 오래된 것부터 버린다.

### 3-3. 작업 우선순위

```
1. 지금 보고 있는 사진
2. 화면에 보이는 썸네일
3. 다음·이전 사진 미리 불러오기
4. 화면 밖 썸네일 (스크롤 방향 먼저)
5. 유사도 분석, 품질 점수, 중복 찾기   ← 사진을 넘기는 동안 자동 정지
```

### 3-4. 대용량 파일 (요구사항 2)

- 100MB 이상인 PSD·TIFF·RAW는 파일 안의 미리보기를 먼저 보여 준다.
- 1억 화소를 넘는 사진은 타일로 나눠서 필요한 부분만 디코딩한다.
- 처음 연 폴더는 썸네일 생성을 바로 시작하고, 다음부터는 디스크 캐시에서 즉시 읽는다.

### 3-5. 속도 목표 (0단계 측정 후 확정)

| 항목 | 목표 |
|---|---|
| 앱 실행 → 첫 사진 표시 (처음 실행) | 맥 0.3초, 윈도우 0.5초 이내 |
| 상주 모드에서 사진 열기 | 0.1초 이내 |
| 2400만 화소 JPEG 첫 화면 | 30ms 이내 (흐린 미리보기는 10ms) |
| 다음·이전 사진 (미리 불러온 경우) | 16ms 이내 (화면 1프레임) |
| 사진 5,000장 폴더의 첫 화면 썸네일 | 캐시 있음 0.05초, 없음 0.3초 |
| 100MB PSD·TIFF·RAW 첫 화면 | 0.1초 이내 |

비교 대상: 맥 미리보기, FastStone, 알씨, 꿀뷰, XnView MP. 윈도우 비교는 윈도우 PC에서 측정한다.

## 4. 요구사항별 구현 방법

### 요구사항 3: 우클릭 빠른 변환 (알씨 방식)

앱 안에서 사진(여러 장 가능)을 우클릭하면 다음 메뉴가 나온다.

```
회전      ▸ 시계방향 90° / 반시계 90° / 180° / 좌우 반전 / 상하 반전   (JPEG는 무손실)
크기      ▸ 50% / 1920px / 1280px / 800px / 직접 입력...
포맷      ▸ JPG / PNG / WebP / AVIF / HEIC(맥) / BMP / TIFF
용량      ▸ 500KB 이하 / 1MB 이하 / 2MB 이하 / 직접 입력...   (품질을 자동으로 찾음)
화질      ▸ 95 / 85 / 75 / 직접 입력...
공유용 저장 ▸ 크기·용량 줄이고 GPS 위치 정보 제거
저장 방식 ▸ 덮어쓰기 / 새 파일(이름_수정) / 지정 폴더로
```
- 여러 장을 선택하면 같은 작업을 일괄 적용한다 (멀티코어 병렬).
- 2단계 후반에 **윈도우 탐색기 우클릭 메뉴**와 **맥 Finder 빠른 동작**에도 같은 메뉴를 넣는다.

### 요구사항 4: 탐색기형 화면

```
┌──────────┬──────────────────────────────┬──────────┐
│ 폴더 트리 │   썸네일 그리드 (가상 스크롤)  │ 정보 패널 │
│ 즐겨찾기  │   ▢ ▢ ▢ ▢ ▢ ▢                │ EXIF     │
│ 드라이브  │   ▢ ▢ ▢ ▢ ▢ ▢                │ 히스토그램│
│ 클라우드  │   ▢ ▢ ▢ ▢ ▢ ▢                │ 별점·태그 │
└──────────┴──────────────────────────────┴──────────┘
```
- 가상 스크롤이라 10만 장 폴더도 부드럽게 움직인다. 썸네일 크기는 슬라이더로 조절한다.
- `Delete`는 휴지통으로 보내고, `Ctrl/Cmd+Z`로 되돌린다. `Shift+Delete`는 영구 삭제이며 확인 창이 뜬다.
- 드래그로 이동·복사한다. 앱 안에서도, 탐색기·Finder와의 사이에서도 된다.
- **숫자키 빠른 이동**: `1`~`9`에 대상 폴더를 지정하고, 사진을 보면서 숫자 하나로 그 폴더로 옮긴다.
- 정렬: 이름, 날짜, 촬영일, 크기, 별점.

### 요구사항 5: 유사 사진 자동 분류 & 베스트 추천 (자동)

**분석은 한 번, 조절은 즉시** (Evoto 방식): 특징값을 한 번 계산해 저장해 두고, 슬라이더를 움직이면 다시 분석하지 않고 결과만 즉시 다시 계산한다.

1. **그룹 만들기**
   - 촬영 시각이 가까운 사진(연사)과, 지각 해시(pHash/dHash)가 비슷한 사진을 묶는다.
   - **유사도 슬라이더**: 거의 같은 사진만 묶을지, 비슷한 장면까지 넓게 묶을지 조절한다 (Peakto 방식).
2. **베스트 점수** (기본, 모델 없이 계산)
   - 선명도: 흔들림과 초점 상태
   - 노출: 하이라이트·그림자가 날아갔는지
   - 노이즈, 해상도
3. **추천 규칙**: 규칙의 우선순위를 사용자가 바꾼다 (예: 선명도 > 노출 > 최신). **그룹당 남길 장수**를 지정할 수 있다 (Evoto 방식).
4. **플래그**: 흐림, 노출 부족, 노출 과다, 정확한 중복 파일.
5. **화면**: 그룹 카드 목록 → 추천 사진에 ★ 표시 → [이 그룹 정리] 또는 [모든 그룹에 적용] → 휴지통으로 이동 (되돌리기 가능).
6. **정확한 중복 찾기**: 파일 내용이 완전히 같은 사진을 찾는다. 크기 → 일부 해시 → 전체 해시 순서로 빠르게 거른다.

> 눈 감김, 표정, 미적 점수는 머신러닝 모델이 필요하다. 6장 C 항목에서 허락을 받은 뒤 추가한다.

**4단계에서 실제로 만든 방식**
- 특징값(사진당 약 15~20ms, 1024px로 줄여 계산): 지문(DCT pHash 64비트), 선명도(5탭 흐림 뒤 라플라시안 분산 ÷ 같은 구역의 대비, 4×4 구역 중 상위 3곳), 밝기 평균·날아감·묻힘 비율, 노이즈(Immerkær), 촬영 시각(EXIF, 없으면 수정 시각). 캐시 폴더 `analysis.db`에 저장해 두 번째부터는 계산하지 않는다.
- 선명도를 대비로 나누는 이유: 같은 장면을 밝게 찍으면 라플라시안 값이 커져서 과노출 사진이 "가장 선명"으로 뽑혔다. 흐림 단계는 노이즈가 많은 사진이 선명하게 잡히는 것을 막는다.
- 묶기: 지문 차이 허용치(묶는 정도 1~5 → 4·7·10·13·16비트). 10초 안에 연달아 찍은 것은 1.3배 너그럽게, 90초 넘게 떨어진 것은 0.6배 엄격하게. 사슬처럼 이어 붙어 다른 장면까지 끌려오지 않게 대표끼리도 비교한다.
- 추천 점수: 기준 순서대로 가중치 1 · 0.5 · 0.25 · 0.12 · 0.06. 직접 남김·별점 준 사진은 우선, 크게 날아가거나 묻힌 사진은 감점, 같은 묶음 안의 똑같은 사본은 맨 뒤.
- 분석은 "비슷한 사진" 화면을 열었을 때만, 코어 절반(최대 6)으로 하고 뷰어·비교 화면이 열려 있으면 멈춘다. 화면을 닫으면 남은 분석도 멈춘다.

### 요구사항 6: 비교 & 나머지 삭제 (수동)

- 선택한 2~9장을 화면 최대 크기로 자동 배치한다 (2분할, 3분할, 2×2, 3×3).
- **확대와 이동을 동기화**한다. 한 장을 확대하면 나머지도 같은 위치가 같은 배율로 확대된다.
- 2장일 때는 **겹쳐 보기와 깜빡이기** 모드로 미세한 차이를 확인한다 (FastStone 방식).
- 클릭하거나 숫자키를 눌러 "남길 사진"을 표시하고, **[선택 외 삭제]**로 나머지를 한 번에 휴지통에 보낸다 (되돌리기 가능).
- **컬링 모드**: `P` 남기기, `X` 버리기, `1`~`5` 별점을 매긴 뒤 "버린 사진 모두 휴지통"으로 정리한다.

### 요구사항 7: 다른 파일 종류 표시

- 메뉴바 `보기 > 파일 종류`: ☑ 이미지 ☐ 동영상 ☐ PDF ☐ 문서 ☐ 기타
- 체크한 종류만 목록에 나오고 썸네일을 만든다. 기본값은 이미지만이다.
- 동영상·PDF 썸네일은 OS 썸네일 엔진을 쓴다 (맥 Quick Look, 윈도우 탐색기 썸네일 캐시). 탐색기가 이미 만든 썸네일이 있으면 그대로 쓰므로 빠르다.
- 동영상은 앱 안에서 바로 재생한다 (mp4 등은 웹뷰 내장 재생).

### 요구사항 8: 간단 편집기

| 분류 | 도구 |
|---|---|
| 기본 | 자르기 (자유, 1:1, 4:3, 16:9 등 비율 고정), 회전, 반전, 기울기 보정, 크기 |
| 저장 | 포맷, 화질, 목표 용량 |
| 보정 | 밝기, 대비, 채도, 자동 보정 |
| 가리기 | 모자이크, 블러 (사각형 영역과 브러시) |
| 그리기 | 밑줄·직선, 화살표, 원·타원, 사각형, 텍스트 (한글, 크기·색·외곽선), 자유 그리기, 형광펜 |
| 공통 | 실행 취소·다시 실행, 도형은 저장 전까지 개체로 남아 다시 수정 가능 |
| 일괄 | 한 장에서 한 편집(자르기 비율, 회전, 크기, 워터마크)을 선택한 사진 전체에 적용 |

**6단계에서 실제로 만든 방식**
- 편집은 모두 "개체 목록"(펜·선·도형·텍스트·모자이크, 자르기 영역, 90° 회전·반전 행렬, 보정 값)으로 남고, 저장 전까지 선택·이동·색 바꾸기·삭제·실행 취소(⌘Z/⇧⌘Z)가 된다.
- 화면에는 뷰어가 이미 가진 화면 크기 사진으로 그리고, 저장할 때 같은 그리기 함수로 원본 해상도에 다시 그린다 (보이는 그대로 저장).
- 원본 해상도 픽셀(RGBA)을 그대로 엔진에 넘기고(`save_edit`, 본문 바이트), 엔진은 변환과 같은 길(크기·형식·화질·새 파일/덮어쓰기·되돌리기)로 저장한다. 맥에서는 원본의 메타데이터(촬영 날짜·위치·카메라)를 이어받고 회전 값은 1로 바꾼다.
- 모자이크는 그 영역을 작게 줄였다가 각지게 키우고, 흐리게는 캔버스 흐림 필터를 쓴다 (없으면 줄였다 부드럽게 키움).

### 요구사항 9: 구글 드라이브 등 외부 드라이브

**방법 A (추천, 설정 없음): 동기화 폴더 인식**
- Google Drive 데스크톱 앱이 만든 폴더(윈도우 `G:` 드라이브, 맥 `~/Library/CloudStorage/GoogleDrive-…`)를 자동으로 찾아 왼쪽 트리에 보여 준다.
- **온라인 전용(아직 내려받지 않은) 파일**을 감지한다. 이런 파일은 내용을 읽지 않고(읽으면 다운로드가 시작됨) OS 썸네일이나 방법 B의 썸네일을 쓴다.
- 이동과 삭제는 파일 정보만 바뀌므로 즉시 끝난다. 동기화는 구글 앱이 알아서 한다.
- OneDrive, Dropbox, iCloud 동기화 폴더도 같은 방식으로 지원한다.

**방법 B (고급): 구글 드라이브 직접 연결**
- 구글 계정으로 로그인한다 (OAuth). 사진 데이터는 구글과 내 PC 사이에서만 오간다.
- 미리보기는 구글 서버가 만든 썸네일을 쓴다. 원본은 열 때만 내려받고, 다음 사진은 미리 받아 둔다.
- 이동과 휴지통 처리는 최대 100개씩 묶어서 한 번에 요청한다.
- 개인용으로 쓰려면 Google Cloud에서 OAuth 클라이언트를 한 번 만들어야 한다 (안내 제공).

**7단계에서 실제로 만든 방식**
- 동영상·PDF 썸네일: 맥 Quick Look(QLThumbnailGenerator, Finder와 같은 엔진). 투명한 곳은 흰 바탕으로 채워 JPEG로 캐시한다.
- 온라인 전용 파일: 맥은 파일 플래그(SF_DATALESS), 윈도우는 파일 속성(RECALL_ON_DATA_ACCESS 등)으로 내용을 읽지 않고 알아낸다. 썸네일은 Quick Look이 클라우드 앱(구글 드라이브·Synology Drive 등)에게 받아 오므로 원본을 내려받지 않는다. 정보 패널, 비슷한 사진 분석, 똑같은 파일 찾기, 날짜·장소 정리의 날짜 읽기도 이런 파일은 내용을 읽지 않는다. 뷰어·편집기에서 열 때만 내려받는다.
- 동영상 재생: 웹뷰 내장 플레이어. 파일은 `isee://file`이 범위 요청(한 번에 최대 8MB)으로 보내 준다. mp4·mov·m4v·webm은 앱 안에서, 나머지는 기본 앱으로.

**분리된 드라이브 오프라인 보기** (Tonfotos 방식): 외장하드나 NAS가 분리되어 있어도 캐시된 썸네일로 목록을 볼 수 있다. 🔜

### 추가 요청 ①: 날짜·장소별 폴더 정리 (메타데이터 활용)

선택한 사진이나 폴더를 우클릭한 뒤 `정리하기`를 누르면 아래 순서로 진행된다.

1. **기준 고르기**: 날짜, 장소, 날짜+장소, 이벤트(촬영 시간 간격으로 자동 구분) 중에서 고른다.
2. **폴더 이름 규칙**: 예시를 보면서 고른다.
   ```
   {년}/{년}-{월}            → 2024/2024-05
   {년}/{월}-{일}            → 2024/05-12
   {년}-{월}-{일} {장소}      → 2024-05-12 제주 서귀포시
   {장소}/{년}-{월}          → 제주 서귀포시/2024-05
   ```
3. **이동 또는 복사**를 고르고, 정리할 위치를 정한다.
4. **미리보기**: 어떤 폴더가 몇 장으로 만들어지는지 트리로 보여 준다. 실행 전에 폴더 이름을 고칠 수 있다.
5. **실행**: 실행한 정리 전체를 `Ctrl/Cmd+Z` 한 번으로 되돌릴 수 있다.

**날짜를 찾는 순서**
1. EXIF 촬영 시각
2. 동영상 생성 시각
3. 파일 이름 속 날짜 (`IMG_20240512_…`, `KakaoTalk_20240512…`, `Screenshot_2024-05-12…`)
4. 파일 수정 시각. 마지막 수단이며, 이 방법으로 찾은 사진은 화면에 따로 표시한다.

**장소를 찾는 방법**: 사진의 GPS 좌표를 지명으로 바꾼다 (역지오코딩).
- **기본은 오프라인**: 지명 데이터를 앱에 넣어 두고 인터넷 없이 바로 바꾼다. 좌표가 밖으로 나가지 않는다.
  - 국내: 행정구역 공개 데이터로 시·도, 시·군·구, 읍·면·동까지 찾는다.
  - 해외: GeoNames 도시 데이터로 찾는다 (예: 일본 오사카시, 프랑스 파리). 한글 지명은 GeoNames 다국어 이름표를 쓰고, 없으면 영문 이름을 쓴다.
- **선택 사항으로 온라인**: 카카오 로컬 API 등에서 관광지나 건물 같은 더 자세한 이름을 받아온다. API 키가 필요하고, 좌표가 해당 서비스로 전송된다.
- **장소 단위**: 국가, 시·도, 시·군·구, 동네 중에서 고른다.
- **위치 정보가 없는 사진**: 카카오톡으로 받은 사진, 화면 캡처, 일부 카메라 사진은 GPS 정보가 없다. 둘 중 하나를 고른다.
  - "위치 없음" 폴더로 보낸다.
  - 시간이 가까운(예: 30분 이내) 앞뒤 사진의 위치로 추정한다. 추정한 사진은 따로 표시한다.

**함께 옮기는 파일**: RAW+JPEG 짝, 아이폰 라이브 포토(HEIC+MOV), 보정 정보 파일(.xmp, .aae)은 함께 옮긴다.

**5단계에서 실제로 만든 방식**
- 지명 데이터 `crates/isee-core/data/places.bin` (2.4MB, `scripts/build_places.py`로 생성): 국내 행정동 경계 3,559곳(admdongkor, 2026-10 기준, 단순화 75만→26만 점), 해외 GeoNames 인구 5천 명 이상 도시 64,622곳(구역·옛 지명 제외), 나라 이름 245개(맥 한국어 지역 이름표). 처음 쓸 때 4ms에 읽는다.
- 국내는 경계 안에 있는지로 찾고(단순화로 생긴 틈·해안은 1.5km 안 가장 가까운 동), 해외는 가장 가까운 도시를 고르되 큰 도시에 가산점(에펠탑 → 근교 소도시 대신 "파리").
- 동영상: MOV·MP4의 애플 메타데이터(현지 촬영 시각·위치) → mvhd 생성 시각(UTC를 이 컴퓨터 시간대로) · ©xyz 위치.
- 파일 이름 날짜: `IMG_20240512_143022`, `KakaoTalk_20240512…`, `Screenshot_2024-05-12-…`, `스크린샷 2024-05-12 오후 2.30.22`, `PXL_…`, 13자리 밀리초.
- 짝 파일: 같은 폴더·같은 이름(확장자 제외)의 사진·동영상·.xmp·.aae·.thm. 대표 파일(일반 사진 > RAW > 동영상)의 날짜를 따르고, 이름이 겹치면 짝 모두 같은 번호 " (2)"를 붙인다.
- 위치 없는 사진 추정: 촬영 시각이 가장 가까운 위치 있는 사진이 30분 안이면 그 지명.
- 이벤트({기간}): 촬영 간격(기본 6시간)이 넘으면 나눈다. 이름은 "2024-05-12~14 제주 서귀포시"처럼 기간과 가장 많이 나온 지명.
- 실행 기록(옮긴 파일, 복사본, 새 폴더)을 남겨 ⌘Z 한 번에 되돌린다. 새 폴더는 비었을 때만 지운다.

**속도 영향**
- EXIF는 파일 앞부분(약 64KB)만 읽으므로 초당 수천 장을 처리한다.
- 지명 변환은 메모리 안에서 검색하므로 사진 1장당 1ms가 걸리지 않는다.
- 보기 속도에는 영향이 없다. 지명 데이터 때문에 설치 용량이 수~수십 MB 늘어난다 (6장 G).

### 추가 요청 ②: 얼굴별 분류 (선택 모듈)

머신러닝 모델이 필요하므로 **기본 앱과 분리된 선택 모듈**로 만든다. 처음 쓸 때 "얼굴 분류 기능 설치"를 누르면 모델을 내려받는다. 이 기능을 쓰지 않는 사람의 앱은 가볍고 빠르게 유지된다.

**동작 방식**
1. **얼굴 찾기**: 사진에서 얼굴 위치를 찾는다. 원본 대신 캐시해 둔 화면 크기 이미지를 써서 빠르다.
2. **얼굴 특징값 계산**: 얼굴마다 "얼굴 지문"(숫자 묶음)을 만든다.
3. **같은 사람끼리 묶기**: 얼굴 지문이 가까운 것끼리 자동으로 묶는다.
4. **이름 붙이기**: 사용자가 묶음에 "엄마", "민준" 같은 이름을 붙인다. 사용자가 확인하거나 고친 결과를 다음 분류에 반영하므로 쓸수록 정확해진다 (Tonfotos 방식).
5. **결과 활용**: 인물별로 보기, 인물로 검색하기, 인물별 폴더로 정리하기

**한 사진에 여러 사람이 있을 때**: 파일 하나를 여러 폴더로 동시에 옮길 수는 없으므로 방식을 고른다.
- **인물 앨범 (추천)**: 파일은 그대로 두고 앱 안에서 인물별로 모아 본다. 디스크를 더 쓰지 않는다.
- **인물별 폴더로 복사**: 사진에 나온 사람 수만큼 복사본이 생겨 디스크를 더 쓴다.
- **주인공 기준 이동**: 가장 크게 나온 얼굴의 인물 폴더로 옮긴다. 여러 명이 비슷한 크기로 나온 사진은 "단체 사진" 폴더로 옮긴다.

**사용할 모델**
- 상업적으로 써도 되는 라이선스의 공개 모델을 쓴다. 후보는 OpenCV Zoo의 YuNet(얼굴 찾기, MIT)과 SFace(얼굴 인식, Apache-2.0)다. 라이선스는 원본 저장소의 LICENSE 파일로 최종 확인한다.
- 정확도가 더 높아도 비상업용 라이선스인 모델은 쓰지 않는다.
- 8단계에서 실제 가족 사진으로 정확도를 비교한 뒤 확정한다.

**8단계에서 실제로 만든 방식**
- 모델: YuNet 2023mar(MIT, 0.23MB) + SFace 2021dec(Apache-2.0, 38.7MB). 저장소의 LICENSE 파일로 확인. "설치"를 눌렀을 때만 GitHub(OpenCV Zoo)에서 내려받고 SHA-256을 확인한다. 앱 데이터 폴더 `models/`에 둔다.
- 실행 엔진: tract (순수 Rust ONNX). 윈도우·맥 같은 코드, 별도 런타임 없음. 앱 크기가 16MB → 34MB로 늘었다 (엔진 + HTTPS).
- 얼굴 찾기: 화면 크기(1024px) 디코딩 → 640×640에 넣어 YuNet (얼굴이 없으면 320으로 한 번 더, 큰 얼굴용). 점수 0.75 이상, 겹침 0.3 이상은 하나로.
- 얼굴 지문: 눈·코·입 5점으로 112×112에 맞춰 정렬(닮음 변환) → SFace 128차원, 길이 1.
- 묶기: 사용자가 정한 얼굴 → 그 사람. 이름 붙은 사람의 평균 지문과 0.45 이상이고 두 번째보다 0.08 이상 가까우면 자동(확인 필요 표시). 나머지는 큰 얼굴부터 가장 가까운 묶음(0.40 이상)에, 마지막에 가까운 묶음끼리(0.45) 합친다. 분석 크기에서 40px보다 작은 얼굴과 한 번만 나온 얼굴은 묶지 않는다.
- "이 사람 아님"은 기억해서 다시 자동으로 넣지 않는다. 앱이 파일을 옮기거나 이름을 바꾸면 얼굴 정보도 따라간다.
- 저장: 앱 데이터 폴더 `faces.db` (얼굴 위치·지문·이름). "얼굴 데이터 지우기"로 전부 지운다.

**정확도를 더 올릴 수 있는 방법 (조사, 2026-10-27)**
- 지금 적용: 고해상도 지문, 확대 조각으로 작은 얼굴 찾기, 좌우 뒤집기 평균, 평균 연결 묶기 (BENCH 9-1)
- 맥 Vision의 얼굴 품질 점수(`VNDetectFaceCaptureQualityRequest`)로 흐리거나 옆을 본 얼굴을 묶기에서 빼기 (맥 전용, 추가 용량 없음)
- 마스크 쓴 얼굴: SFace는 마스크 얼굴로 학습되지 않아 크게 틀린다. 마스크 얼굴을 따로 표시하고 이름 붙은 사람에게 자동으로 넣지 않는 것이 안전하다
- 더 정확한 인식 모델(ArcFace·AdaFace 등)은 대부분 학습 데이터가 비상업 라이선스라 쓰지 않는다. 상업 사용 가능한 큰 모델이 나오면 교체를 검토
- 사용자의 확인이 가장 효과적: 이름을 붙이고 "모두 맞음"·"이 사람 아님"을 누를수록 평균 지문이 좋아져 다음 분류가 정확해진다

**한계**: 아이의 성장 전후 사진, 옆얼굴, 마스크, 선글라스는 틀리게 묶일 수 있다. 그래서 자동 결과를 사용자가 확인하는 화면을 둔다.

**개인정보**: 얼굴 데이터는 내 컴퓨터의 데이터베이스에만 저장하고, 언제든 전부 지울 수 있다.

**속도 영향** (6장 H)
- 보기 속도에는 영향이 없다. 분석은 백그라운드에서 하고, 사진을 넘기는 동안에는 멈춘다.
- 분석 시간은 사진 1만 장에 수 분 정도로 예상한다. 맥은 Core ML, 윈도우는 DirectML로 그래픽 가속을 쓰면 더 빨라진다. 실제 숫자는 측정해서 보고한다.
- 모델과 실행 엔진 때문에 설치 용량이 약 50MB 늘어난다. 모듈을 설치한 경우에만 해당된다.

### 요구사항 10: 추가 제안 기능

| 기능 | 효과 | 속도 영향 |
|---|---|---|
| 휴지통 + 되돌리기 (`Ctrl/Cmd+Z`) | 빠르게 지워도 안전하다 | 없음 |
| 숫자키 빠른 이동 폴더 | 보면서 바로 분류한다 | 없음 |
| 컬링 모드 (P/X/별점) | 키보드만으로 수백 장을 정리한다 | 없음 |
| 정확한 중복 찾기 | 같은 파일을 정리해 용량을 확보한다 | 백그라운드 |
| RAW+JPEG 짝 처리 | 같이 지우고 같이 옮긴다 | 없음 |
| 공유용 저장 (GPS 제거, 크기 축소) | 개인정보 보호 | 없음 |
| 날짜 보기 (타임라인) | 여러 폴더를 날짜순으로 본다 | 색인 필요, 백그라운드 |
| 앨범·즐겨찾기 (파일은 그대로 두고 묶기) | 원본 위치를 유지한다 | 없음 |
| 속도 표시 HUD (디코딩 ms) | 속도를 눈으로 확인한다 (개발용) | 없음 |
| 지도 보기 (GPS) | 장소별로 본다 | 인터넷 지도 필요, 🔜 |

> 날짜별 폴더 정리와 얼굴별 분류는 위의 추가 요청 ①, ②로 옮겼다.

## 5. 개발 단계

| 단계 | 내용 | 끝나면 직접 확인할 것 |
|---|---|---|
| **0. 기반** | 프로젝트 구조, Rust 엔진 뼈대, **속도 측정 도구**, 테스트용 사진 세트 (작은 JPEG부터 1억 화소, RAW, HEIC, PSD까지) | 실측 숫자 보고 → 속도 목표 확정 |
| **1. 빠른 뷰어 + 탐색기 (MVP)** | 폴더 트리, 썸네일 그리드와 캐시, 크게보기·전체화면·확대·이동, 미리 불러오기, 휴지통 삭제와 되돌리기, 이동·복사, 숫자키 이동, 파일 종류 필터, 기본 뷰어 연결 | **속도 체감 테스트** (가장 중요한 단계) |
| **2. 우클릭 빠른 변환** | 무손실 회전, 크기, 포맷, 목표 용량, 화질, 일괄 처리, 이름 일괄 변경, 워터마크, 공유용 저장, 탐색기·Finder 우클릭 메뉴 | 알씨와 비교 |
| **3. 비교 & 수동 정리** | 비교 화면 (2~9장, 확대 동기화, 겹쳐 보기), 선택 외 삭제, 컬링 모드, 별점 | 실제 사진 폴더로 정리해 보기 |
| **4. 유사 사진 자동 정리** | 그룹 만들기, 유사도 슬라이더, 베스트 점수, 규칙 우선순위, 남길 장수, 플래그, 정확한 중복 찾기 | 추천 결과가 맞는지 확인 |
| **5. 날짜·장소 정리** | 날짜 찾기, 오프라인 지명 변환, 폴더 이름 규칙, 미리보기, 라이브 포토·RAW 짝 함께 옮기기, 한 번에 되돌리기 | 휴대폰 사진 폴더로 정리해 보기 |
| **6. 편집기** | 자르기부터 텍스트·모자이크·그리기까지 (요구사항 8 전체) | 편집 후 저장 결과 확인 |
| **7. 동영상·PDF·클라우드** | OS 썸네일 엔진 연동, 구글 드라이브 방법 A, 그다음 방법 B | 구글 드라이브 폴더로 테스트 |
| **8. 얼굴별 분류 (선택 모듈)** | 얼굴 찾기·인식 모델, 같은 사람 묶기, 이름 붙이기와 학습, 인물 앨범·폴더 정리 | 가족 사진으로 정확도 확인 |
| **9. 배포** | 윈도우 설치 파일, 맥 dmg, 자동 업데이트 | 다른 PC에 설치해 보기 |

5~8단계의 순서는 원하시는 대로 바꿀 수 있다.

각 단계가 끝날 때마다 속도를 측정한다. 이전 단계보다 느려졌으면 원인 기능과 함께 보고한다.

|---|---|---|---|
| A | **화면 기술 Tauri (웹뷰)** | 처음 실행할 때 0.1~0.5초가 더 걸림. 사진 넘기기 속도와는 무관 | Tauri + 상주 모드 옵션. 0단계 측정 후 다시 보고 |
| B | **디스크 썸네일 캐시** | 디스크를 사용함 (사진 1만 장당 약 200MB). 대신 두 번째부터는 매우 빠름 | 켬. 용량 한도 설정 가능 |
| C | **머신러닝 베스트 추천** (눈 감김, 표정, 미적 점수) | 설치 용량이 수십~수백 MB 늘고 분석 시간이 늘어남. 보기 속도에는 영향 없음 | 우선 제외. 4단계 후 결정 (맥은 OS 내장 Vision을 쓸 수 있어 용량 부담이 적음) |
| D | **폴더 실시간 감시** | 파일이 아주 많은 폴더에서 CPU를 조금 씀 | 현재 폴더만 감시 |
| E | **동영상·PDF 썸네일** | 생성에 시간이 걸림 | 꺼짐 (요구사항 7대로 메뉴에서 켬) |
| F | **윈도우에서 HEIC 보기** | OS 확장 코덱을 쓰거나, 디코더를 직접 넣어야 함 (HEVC 특허 문제) | 윈도우 HEIF 확장 코덱 사용, 없으면 설치 안내 |
| G | **지명 데이터 내장** (장소별 정리) | 설치 용량이 수~수십 MB 늘어남. 보기 속도와는 무관 | 국내 행정구역과 해외 도시 데이터를 내장 |
| H | **얼굴 분류 모듈** | 설치 시 약 50MB 추가. 분석은 백그라운드에서 하며 1만 장에 수 분 예상 | 선택 모듈로 만들고 처음 쓸 때 설치 |

- **결정 (2026-10-26)**: 윈도우 PC 있음(설치 테스트는 사용자), GitHub Actions로 빌드, 코드는 비공개 저장소 `janghwansangai/isee`(2026-10-30 공개로 전환), 설치 파일·업데이트는 공개 저장소 `janghwansangai/isee-releases`, 코드 서명 없이 먼저.
- **배포 서명** (7단계에 결정)
  - 맥: Apple Developer 계정(연 $99)이 없으면 "확인되지 않은 개발자" 경고가 뜬다.
